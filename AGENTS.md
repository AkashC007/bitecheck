# BiteCheck contributor instructions

- Inspect the repository before editing.
- Teach the relevant concepts before implementing them.
- Explain concepts and decisions without assigning practice tasks or knowledge checks.
- Work on one milestone and one small step at a time.
- Stop for user approval before starting another milestone.
- Do not rewrite established architecture without approval.
- Do not modify unrelated modules or neighboring portfolio projects.
- Keep external providers behind replaceable interfaces when introduced.
- Never expose secrets in frontend code.
- Never commit `.env`, `.env.local`, or credentials.
- Run focused tests after code changes and report actual results.
- Use TypeScript strict mode and typed Python.
- Add tests for important backend logic.
- Record important decisions in `docs/project-decisions.md`.
- Update `docs/learning-journal.md` at milestone completion.
- Keep synthetic data clearly labelled.
- Do not scrape restricted sources.
- Preserve existing functionality unless explicitly instructed otherwise.
